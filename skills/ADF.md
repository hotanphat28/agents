# Atlassian Document Format (ADF)

Shared reference for `write-story`, `write-bug`, `write-epic`, `write-initiative`, and `write-design-doc`, single source of truth for Jira/Confluence markup and attachment handling. Do not restate this content inside those skills; point here instead.

## How conversion works
The Jira and Confluence MCP tools (`create_issue`/`update_issue`, `create_page`/`update_page`) take content as **pure CommonMark Markdown only**. The server converts it to wiki markup and then to Atlassian Document Format (ADF); it does not understand literal wiki markup (`h2.`, `{quote}`, `{code}`) or macros (`{panel:type=warning}...{panel}`) typed directly, those are stored as literal garbage text. Only write standard Markdown, never hand-write wiki markup or macros.

## Supported styling
| Want | Write in Markdown | Renders as |
|---|---|---|
| Heading | `## Heading` (levels 1-6) | Heading |
| Bold | `**text**` | Entities / components |
| Italic | `*text*` or `_text_` | Emphasis |
| Bold + italic | `***text***` | APIs / topics |
| Strikethrough | `~~text~~` | Strikethrough |
| Inline code | `` `code` `` | Fields / variables / values |
| Code block | fenced with a language tag | Code block with syntax highlighting |
| Quote / callout | `> text` | Blockquote (also the panel substitute, see below) |
| Bullet list | `* item` | Bullet list |
| Numbered list | `1. item` | Ordered list |
| Nested list | indent by 2 spaces | Nested list |
| Table | GFM pipe table | Table |
| Link | `[text](https://full/url)` | Link, always use the full browse URL |
| Horizontal rule | `---` | Divider |

Never use checkbox syntax (`- [ ] item`), it does not render reliably in ADF; use plain bullets (`*`) for any list, including acceptance criteria, instead.

## Formatting choices for scannability
ADF element choices that aid scanning:
* Use `###` subheadings to break up a long `##` section instead of one dense block of text.
* Bold only the term/field/entity that anchors a line (`**Component**: does X`), not whole sentences, over-bolding defeats scanning.
* Use a table instead of prose whenever comparing 3+ items across the same attributes (environments, options, before/after).
* Numbered lists only for steps that must happen in order (repro steps); bullets for everything else.

## No panel macros, use a blockquote instead
Panel macros (info/warning/success/error) are **not** supported through this Markdown path, whether typed as wiki markup (`{panel:type=warning}...{panel}`) or as GitHub-style alert blocks (`> [!WARNING]`); both are stored as literal text instead of a real panel. When a template says "use a warning panel" (e.g. the AI-generated disclaimer line), render it as a blockquote with a bold, emoji-led lead-in instead:

```markdown
> **⚠️ Warning:** This ticket was generated by an AI assistant and must be verified and updated as needed.
```

Swap the emoji/label for the intent: `ℹ️ Note`, `⚠️ Warning`, `✅ Success` / `Tip`, `🛑 Error`.

## Rich media & attachments
Local file paths (e.g. `![alt](/local/path.png)`) do not work in Jira or Confluence, Atlassian servers can't reach your filesystem. Upload the image/diagram/screenshot via the MCP attachment tool first, then embed it using the attachment syntax (e.g. `!filename.png!`), never the local path.
